零 Token 设计

Zero-Token Design — when the product stops burning its own tokens
先问你一个问题，不用回答，带着它听这节课 ——
▎如果你要做一个 AI 简历产品，用户每改一次简历都要调一次大模型——这笔 token 钱谁出？有没有可能，你一分钱推理费都不用付，产品还照样是 AI 产品？
ONE-LINE ESSENCE · 一句话本质

零 token 设计 = AI 产品不再在自己服务器上烧自己的 token 跑推理，而是让用户用他手里已有的 agent（Codex / Claude Code / Cursor）去干活，产品只负责把结果接住、漂亮地承载和分发。

2023
ACT Ⅰ · THE OLD DEFAULT

一 · 要挑战的旧默认：运行时烧 token

Everyone did it this way — so it must be the only way?

你脑子里大概率有个默认设定，2023 年以来几乎所有 AI SaaS 都这么做：用户每点一次 → 产品后台调一次模型 → 产品替用户付推理费。网页里塞个聊天框，每次交互都是一次 API 调用，账单记在产品方头上。

"That made sense in 2023, because back then, most users didn't really have their own AI workspace."
2023 年这合理——那时用户手里没有自己的 AI 工作区，产品只能自己包办推理。
Lawted · Zero-Token Design

他要挑战的不是这个做法本身，而是「这是唯一做法」这个假设。很多人以为 AI 产品必须自己烧 token，其实那只是用户还没有自己的 agent 时的过渡形态。

AGENT
ACT Ⅱ · THE NEW PREMISE

二 · 为什么「现在」才成立：用户的 agent 工作区

2023 didn't have this. 2026 does. That's the whole difference.

前提变了。Codex、Claude Code、OpenCode、Cursor 这些本地 agent 已经成熟——

agent-workspace — capabilities check

"They are no longer just chatboxes. They can read your directory, read your documents, run bash commands, edit code, run npx or uvx, and handle a whole workflow inside the user's own environment."
它们不再是聊天框——能读目录、读文档、跑 bash、改代码、执行 npx/uvx、在用户自己的环境里跑完一整套工作流。
Lawted · Zero-Token Design

正因为用户手里已经有了这么强的 agent，推理才可能「外包」给用户。2023 年不成立、2026 年成立——差的不是模型，是这个前提。

顺带一说 · META

原版那所学校（ha7ch.school）本身就是一个例子——课程校验、更新、读讲义，全是 agent 在干，ha7ch.school 一个 token 都没烧。

HANDOFF
ACT Ⅲ · THE DIVISION

三 · 分工原则：agent 干活，产品接结果

Inference belongs to the agent. Hosting belongs to the product.
「让用户的 agent 干活，让产品接住结果。」
"Let the user's agent do the work. Let the product handle the result."

推理归 agent，承载归产品。拿作者自己的产品 CV.pro（一个简历产品）拆开看分工——用户复制一段快速启动 prompt（里面含 npx 命令），贴进自己的 agent；agent 跑命令、解析文件、处理错误、生成结构化 schema，推回 CV.pro：

ACT Ⅳ · NOT BYOK · 重点

四 · 最容易混的点：它和 BYOK 不是一回事

Same bill? No. Completely different burden.

BYOK（Bring Your Own Key，用户自带 API key）：用户去申请 key、做配置、搞懂计费、把 key 填进你的产品。原文说得很直白——

two roads — who carries the burden?
✗BYOK · 自带钥匙
// 2023 的惯性延长线

02复制密钥：sk-proj-9xK2f••••••••••••钥匙交到了别人产品的设置页里
03搞懂 token 计费模型、设充值上限
04在产品设置页把 key 填进去、测试连通
账单 → 转给用户
UX 负担 → 仍全部压在用户身上

✓零 TOKEN · 对接已有工具
// 2026 的新前提

推理 → 搬进用户工作区

ACT Ⅵ · MYTHS & GRADUATION

六 · 三个常见误解，听到就纠正 & 小结

Three myths to unlearn — then close the bill.
❌ MYTH 01
「零 token = 不需要 AI / 不算 AI 产品」
✓ 作者开篇就堵了这句。CV.pro 依然是 AI 产品——解析、定制、改写全是 AI 干的，只是推理不发生在它自己服务器上。
点开纠正
❌ MYTH 02
「零 token = BYOK 换个说法」
✓ 账单转给用户 ≠ 推理搬到用户工作区，UX 负担的落点完全不同（见第四幕）。
点开纠正
❌ MYTH 03
「零 token 只是个省钱技巧」
✓ 省钱只是结果，本质是产品定位变了：你不做推理引擎，你做 agent 生态里的承接与分发层。
点开纠正
SUMMARY · 小结
旧默认产品烧自己的 token 包办推理 → 2023 年合理，因为用户没有自己的工作区
